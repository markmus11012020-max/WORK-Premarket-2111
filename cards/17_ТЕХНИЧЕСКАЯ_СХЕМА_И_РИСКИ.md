# Карточка 17. Техническая схема и риски

**Вопрос:** Как устроено решение технически, что уже подтверждено и какие риски остаются?

**Лимит:** 5000 знаков.

**Объём ответа:** 954 знака с пробелами.

## Ответ для платформы

Компоненты: интерфейс, AI-агент на LangGraph, T-Invest MCP read-only, RAG-слой, детерминированное ядро, LLM, HITL и аудит.

Поток: событие → LangGraph → MCP и RAG → ядро → LLM → риск-бриф → HITL. LangGraph хранит состояние, выбирает ветки, делает retry и чекпоинты. RAG ищет 3–5 фрагментов по эмбеддингам с метаданными и цитатами.

Подтверждено документацией MCP: портфель, котировки, стакан, новости, поиск; sandbox и read-only. Проверить: оферты и амортизацию, кредитные события и рейтинги, глубину новостей, лимиты MCP, данные по ВДО.

Риски:

• Галлюцинации → числа из ядра, RAG с цитатами, «ПРОВЕРИТЬ», 20–30 кейсов.

• Нерелевантный RAG → неверный контекст. Мера: гибридный поиск, фильтры по эмитенту и дате, реранк, порог.

• Сложность LangGraph → падения и задержки. Мера: 7–8 узлов, чекпоинты, retry, логирование.

• Нет данных или MCP → «нет данных / ПРОВЕРИТЬ», резерв, без выдумок.

• Комплаенс → HITL, запрет автоторговли, токены на сервере.

## Пометки

- RAG не заменяет расчёты и MCP.
- RAGAS — оценка, не runtime.
- LangGraph — техническая реализация, не новый продуктовый компонент.
- «Подтверждено» означает документацией, а не проверено в sandbox.
