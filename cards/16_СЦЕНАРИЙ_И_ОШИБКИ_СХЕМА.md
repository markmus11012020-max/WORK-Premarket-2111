# Карточка 16. Сценарий и ошибки — вариант со схемой

**Вопрос:** Как выглядит основной пользовательский сценарий и что происходит при ошибках?

**Схема:** `materials/16_SCENARIO_SCHEME.pdf`

**Лимит:** 5000 знаков.

**Объём ответа:** 796 знаков с пробелами. Запас до 1000: 204 знака.

## Ответ для платформы

Основной сценарий — на схеме. Кратко: пользователь видит событие → карточка события (источник, дата, бумаги, статус «подтверждено / проверить») → T-Invest MCP read-only (портфель, котировки, новости) → детерминированное ядро (доля, концентрация, YTM/YTC, НКД, ликвидность, риск-гейт) → LLM (факты vs слухи, 2–3 сценария) → риск-бриф → HITL.

Схема показывает основной путь и четыре ветки восстановления.

Ошибки: нет данных или MCP — «нет данных / ПРОВЕРИТЬ», fallback на раскрытия или ручной ввод; AI ошибся — показываем источник и расчёт, даём исправить и перезапустить; конфликт данных — HITL и ручная проверка; запрос невозможен — объясняем, чего не хватает. Сделки не исполняются. HITL обязателен для HIGH/CRITICAL и любых сделок. Пользователь на каждом шаге видит, что проверено, а что нет.

## Пометки

- Схема прикладывается отдельным PDF.
- В тексте нет выдуманных результатов.
- Сделки не исполняются; HITL обязателен.
