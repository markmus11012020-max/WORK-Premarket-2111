# Карточка 09. Зачем нужен T-Invest MCP

**Вопрос:** Зачем в решении нужен T-Invest MCP?

**Лимит:** 5000 знаков.

**Объём ответа:** 3700 знаков с пробелами / 3116 без пробелов. Запас до лимита: 1300 знаков.

## Ответ для платформы

T-Invest MCP нужен, чтобы решение работало не с «рынком вообще», а с конкретным портфелем пользователя. Это слой доступа к брокерским данным и инструментам, через который агент получает портфель, котировки, новости и события, а затем передаёт их в детерминированное ядро и LLM.

Где и какие данные используем

1. Старт сценария. Пользователь задаёт вопрос или приходит событие. MCP: новости и сентимент по эмитенту, поиск бумаги по ISIN или тикеру.

2. Контекст портфеля. MCP: состав портфеля, позиции, доли, свободные средства.

3. Оценка бумаги. MCP: котировки, объёмы, стакан, параметры выпуска.

4. Проверка события. MCP: новости и сентимент; официальные раскрытия эмитента — отдельный источник.

5. Расчёт и риск-гейт. MCP поставляет данные, считает детерминированное ядро: доходность к оферте или погашению, НКД, дюрация, концентрация, ликвидность.

6. Объяснение и сценарии. LLM использует только подтверждённые данные MCP и ядра.

7. HITL. Человек подтверждает решение; торговые методы MCP в MVP не используем.

8. Аудит. Фиксируем, какие данные MCP получены и какие проверки выполнены.

Что подтверждено документацией

• Портфель, позиции, свободные средства.

• Котировки, объёмы, стакан.

• Поиск бумаг и параметры выпуска.

• Новости и сентимент.

• Операции, налоги, анализ сделок.

• Sandbox-среда и read-only доступ.

Это подтверждено документацией, но перед демо проверяем в sandbox: состав полей, задержки и лимиты.

Что предстоит проверить

• График оферт и амортизации в структурированном виде.

• Кредитные события, рейтинги и финансовые показатели эмитента.

• Глубину истории новостей и задержку.

• Доступность аналитики и риск-оценок.

• Лимиты sandbox и поведение при ошибках.

• Полноту данных по ВДО и флоатерам.

Если возможность недоступна

• Нет портфеля — нет персонализации. Для демо используем sandbox-портфель или ручной ввод, но в продукте без портфеля сценарий не работает.

• Нет новостей — используем раскрытия и RSS, помечаем «ПРОВЕРИТЬ»; покрытие ниже.

• Нет графика оферт и амортизации — ядро работает на ручных данных, автоматическое напоминание не обещаем.

• Нет стакана — оценка ликвидности упрощается, риск-вердикт менее точный.

• Нет аналитики — не критично: ядро считает само, аналитика была бы дополнением.

• Нет торговых методов — не критично: автоторговли нет, HITL остаётся.

Если MCP недоступен целиком, мы не подменяем данные: демо идёт на фикстурах с явной пометкой, а продуктовый сценарий считается заблокированным до восстановления доступа.

Как проверим

• Статус подключения в MCP-клиенте: connected.

• Запрос портфеля и позиций в sandbox.

• 5–10 новостей по эмитентам: наличие, дата, сентимент.

• Стакан и объёмы по 2–3 выпускам.

• Сверка данных с MOEX ISS и раскрытием эмитента.

• Фиксация: метод, поле, задержка, ограничение.

Что MCP не заменяет

MCP не заменяет детерминированное ядро, комплаенс и человека. Он не гарантирует полноту данных и не является источником инвестиционной рекомендации. Если данных нет, MCP не «додумывает» их.

Почему MCP, а не только Open API

MCP даёт агенту стандартный доступ к инструментам и данным, меньше кастомной интеграции и единый контур с sandbox. Open API остаётся fallback для методов, которых не хватает в MCP. Решение не зависит от одного метода: если чего-то нет, честно меняем сценарий, а не выдумываем данные.

Границы

MCP используем read-only. Токен хранится на backend, не в браузере и не в Git. Торговые методы не являются частью MVP: продукт не совершает сделок.

Вывод

MCP нужен, потому что без него агент не знает портфель и превращается в общий новостной объяснитель. С MCP он отвечает на вопрос, что это значит для денег пользователя, и делает это на подтверждённых данных.

## Пометки

- «Подтверждено документацией» не равно «проверено в sandbox».
- Не обещать автоматическое отслеживание оферт и амортизации до проверки данных.
- Торговые методы MCP не входят в MVP.
- Токен и портфель не передаются в LLM и не хранятся в репозитории.
